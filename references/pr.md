# 角色与任务：生成开源项目 PR 描述

请根据我本次的代码改动和测试结果，帮我起草一份专业、克制的 Pull Request 描述。

## 一、输入信息
- **关联 Issue**：{ISSUE_LINK_OR_NUMBER，如 Fixes #123}
- **目标仓库语言偏好**：{中文 / 英文，默认请参考仓库近期合并的 PR 语言}
- **改动摘要与测试结果**：{粘贴阶段三输出的改动摘要与测试执行结果}

## 二、写作要求
1. 提交类型（`type`）参考：`feat` / `fix` / `refactor` / `test` / `docs` / `perf` / `chore`。
2. 语气客观、专业、精炼，直奔主题，不带主观情绪或夸张修辞。
3. 若目标仓库存在 `.github/PULL_REQUEST_TEMPLATE.md`，请优先对齐仓库自带的 PR 模板结构；若无，请严格按下方结构输出。

## 三、PR 描述模板

**标题**：`{type}({scope}): {一句话清晰描述本次改动}`

### Problem
- 客观陈述当前存在的问题、触发条件及具体表现。
- 如有对应 Issue，在此处关联（如 `Fixes #xxx` 或 `Resolves #xxx`）。

### Solution
- 简明描述本 PR 的解决思路，以及为什么选择当前方案（例如相比其他做法在兼容性或改动范围上的优势）。

### Changes
- 列出本次新增、修改或删除的核心文件、函数与关键逻辑变更。

### Testing
- 说明如何复现原问题及验证本改动有效（附可执行的测试命令）。
- 列出新增或更新的测试用例覆盖了哪些场景（正常路径、边界异常、向后兼容性）。

### Notes for Review
- 标出需要 Reviewer 重点关注的代码位置、边界权衡，或有意为之的设计决策（如为什么某处保持原样未做改动）。
